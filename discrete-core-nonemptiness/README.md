# Exact artifact for discrete-core nonemptiness with at most eight voters

This repository contains the source, proof-relevant data, exact replay programs,
manifests, and reproduction scripts for the computer-assisted part of the
bounded-voter argument. The mathematical manuscript is distributed separately.

> **Release state.** This is a **data-complete exact proof artifact**. The full
> eight-column square-stage files are present, including the 9,105,190 canonical
> positive-dual kernels, 1,049,187 hard-cell records, 1,049,187 accepted
> certificates, and the eight-byte zero-failure stream. The complete verifier
> audits the kernel universe, checks exact hard-record coverage, and replays every
> certificate with independent signed-rational and GMP implementations.

The artifact is an exact computer-assisted proof relative to the mathematical
reductions and ordinary computational trusted base described in the manuscript
and `docs/TRUST_BOUNDARY.md`. It is not a proof-assistant formalization.

## Logical modules

- `n6` is the six-voter tight-cell classification used as the induction base.
- `n7` is the seven-voter surplus-cell and puncture classification.
- `n8/m4` through `n8/m8` are eight-voter computations indexed by the number
  `m` of fractional columns. Thus `data/n8/m6` is **not** six-voter data.
- `optional_cross_checks/independent_six_voter_proof` is a logically independent
  older verification and is not on the main dependency chain.

## Referee-scale verification

From the repository root, run:

```bash
scripts/quick_verify.sh
```

This verifies the package manifest, recompiles the authoritative checkers,
checks the six- and seven-voter classifications, verifies all eight-row branches,
audits all 9,105,190 square kernels, proves the hard/certificate/failure record
bijection, and replays every certificate in a gap-free contiguous partition with
both exact `m=8` backends, requiring equality of all aggregate proof fields.
For referee-scale wall time, the complete certificate stream is split into an
exact gap-free set of contiguous record intervals; both backends check every
interval and must return identical summed counters and rational minima. Set
`REPLAY_JOBS=N` to override the default CPU-count-based parallelism.

The floating-point proposer is search-only. A regenerated certificate stream may
select different valid committees. Mathematical acceptance requires complete
hard-record coverage, zero failures, and successful exact replay—not byte
identity with one proposal stream.
The exact-valid release stream and the corresponding manuscript-metadata update
are documented in `docs/CERTIFICATE_STREAM_PORTABILITY.md`.

Additional interfaces:

```bash
scripts/verify_predecessors.sh
scripts/verify_n8_available.sh
scripts/verify_n8.sh
scripts/test_n8_release_regressions.sh
scripts/independent_m8_binary_audit.py
```

The last command is a small parser-independent structural audit of the four
deposited square-stage streams. Its recorded output is
`logs/n8/proof_complete_independent_binary_audit.log`.

## Full regeneration

Run all eight-row levels from canonical supports with:

```bash
JOBS=8 CHUNK_SIZE=100000 scripts/regenerate_n8.sh /path/to/new/n8-run
```

Resume an interrupted run, with the original chunk layout, using:

```bash
RESUME=1 JOBS=8 CHUNK_SIZE=100000 \
  scripts/regenerate_n8.sh /path/to/new/n8-run
```

Every reusable key list, scan chunk, proposal chunk, and exact-replay log is
SHA-256-bound to its executable, command, inputs, parameters, and output. A
changed input or executable invalidates dependent outputs; incompatible chunk
layouts are rejected.

For all modules:

```bash
scripts/full_regenerate.sh /path/to/new/all-modules
```

Scope note: this executes every packaged regeneration and verification stage,
but two small certificate inputs remain deposited rather than generated by the
package. The seven-voter run verifies
`data/n7/puncture_certificates.json`, and the eight-voter `m=6` stage serializes
`data/n8/m6/m6_unresolved_certificate_summary.csv` before exact replay. The
matrix universes, floor-region scans, hard-record streams, and the `m=7,8`
certificate proposals are regenerated. Accordingly, this interface should not
be described as a fully source-independent or separate-hardware replication.

## Proof data

The four square-stage files are documented in
`data/n8/m8/REQUIRED_FILES.md`. Completion evidence and exact aggregate results
are in `summaries/n8/m8_full_completion.json` and
`logs/n8/full_m8_regeneration_console.log`.

## Toolchain

The eight-row code requires C++20, Boost headers, GMP/GMPXX, Python 3.10+, a
little-endian host, and IEEE-754 binary64. The binary-format self-test audits the
24-byte hard-record and 64-byte certificate layouts before computation.
